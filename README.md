# transporter_ws

ROS 2 workspace for the transporter robot: a skid-steer base driven by 4 ODrives, and two manipulators (one shared pump plus up/down outputs for each side) driven by an STM32 board running micro-ROS. Both are teleoperated with a PS5 controller.

🇹🇭 ภาษาไทย: [README_TH.md](README_TH.md)

---

## 1. How to install

Tested on **Ubuntu 24.04 + ROS 2 Jazzy**.

### 1.1 Required packages

| Requirement | Used by | Install |
|---|---|---|
| ROS 2 Jazzy (desktop or ros-base) | everything | [docs.ros.org](https://docs.ros.org/en/jazzy/Installation.html) |
| `colcon`, `rosdep` | build | `sudo apt install python3-colcon-common-extensions python3-rosdep` |
| `ros-jazzy-joy` | PS5 controller → `/joy` | `sudo apt install ros-jazzy-joy` |
| `micro_ros_agent` | bridge to manipulator board | build from source (1.2) |
| `odrive` Python package (0.6.x) | `transporter_odrive` | `pip install odrive` (1.3) |
| STM32CubeIDE + Docker | build/flash firmware only | [st.com](https://www.st.com/en/development-tools/stm32cubeide.html) |

### 1.2 micro-ROS agent

```bash
source /opt/ros/jazzy/setup.bash
mkdir -p ~/microros_ws/src && cd ~/microros_ws
git clone -b jazzy https://github.com/micro-ROS/micro_ros_setup.git src/micro_ros_setup
rosdep update && rosdep install --from-paths src --ignore-src -y
colcon build && source install/local_setup.bash
ros2 run micro_ros_setup create_agent_ws.sh
ros2 run micro_ros_setup build_agent.sh
echo "source ~/microros_ws/install/local_setup.bash" >> ~/.bashrc
```

### 1.3 ODrive USB access

```bash
pip install --upgrade odrive          # on Ubuntu 24.04 add --break-system-packages, or use a venv
sudo "$(which odrivetool)" udev-setup  # allow USB access without sudo
```
Check that all 4 ODrives are visible with `odrivetool`. Their serial numbers must match `wheel_serials` in [mobile.yaml](src/transporter_bringup/config/mobile.yaml).

### 1.4 Serial port and controller permissions

```bash
sudo usermod -aG dialout,input $USER   # log out / in afterwards
```
Give the manipulator board a fixed name with a udev rule, for example `/etc/udev/rules.d/99-transporter.rules`. Replace the IDs with the values from `udevadm info -a /dev/ttyACM0`:
```
SUBSYSTEM=="tty", ATTRS{idVendor}=="0483", ATTRS{idProduct}=="374b", ATTRS{serial}=="<board serial>", SYMLINK+="ttyTransporterLeftMani"
```
```bash
sudo udevadm control --reload-rules && sudo udevadm trigger
```
Pair the PS5 controller over Bluetooth (hold **PS + Create** until it blinks), or plug it in with USB.

### 1.5 Build the workspace

```bash
git clone git@github.com:SOLAR-NEXT-GEN/transporter_ws.git
cd transporter_ws
source /opt/ros/jazzy/setup.bash
rosdep install --from-paths src --ignore-src -y
colcon build --symlink-install
source install/setup.bash
```

> **ROS_DOMAIN_ID:** the manipulator firmware uses domain **124**. Run every terminal with `export ROS_DOMAIN_ID=124`, or add it to `~/.bashrc`.

### 1.6 Firmware (manipulator board)

Open `firmware/transport_mani` in STM32CubeIDE, then build and flash it. The micro-ROS static library is generated by Docker during the first build. Pin configuration and the GPIO truth table are described in [section 5](#5-manipulator-firmware).

## 2. Workspace packages

| Package | What it does |
|---|---|
| `transporter_joy` | Converts PS5 input (`/joy`) into `cmd_vel`, manipulator commands and the ODrive index-search request. Contains the deadman logic and joystick-loss safety. |
| `transporter_mobile` | Differential/skid-steer kinematics: `cmd_vel` → left/right wheel speed (`wheels/cmd`). |
| `transporter_odrive` | USB driver for the 4 ODrives: index search, arming, velocity control, watchdog and fault handling. |
| `transporter_manipulator` | Forwards `manipulator/cmd` to the firmware (`manipulator/hw_cmd`) at a fixed rate, and sends HOLD on timeout. |
| `transporter_bringup` | Launch files and all configuration (`config/*.yaml`). |
| `firmware/transport_mani` | STM32G474 + micro-ROS firmware that drives the manipulator GPIO (pump, up and down for each side). |

### Topics and services

| Name | Type | From → To |
|---|---|---|
| `/joy` | `sensor_msgs/Joy` | `joy_node` → `transporter_joy` |
| `/cmd_vel` | `geometry_msgs/Twist` | `transporter_joy` → `mobile_controller` |
| `/wheels/cmd` | `std_msgs/Float64MultiArray` `[left, right]` rad/s | `mobile_controller` → `odrive_node` |
| `/wheels/state` | `std_msgs/Float64MultiArray` `[left, right]` rad/s | `odrive_node` |
| `/odrive/state` | `std_msgs/String` | `odrive_node` (`DISCONNECTED`, `IDLE`, `INDEX_SEARCH`, `ARMING`, `ARMED`) |
| `/odrive/index_search` | `std_srvs/Trigger` | index search on all wheels, then arm |
| `/odrive/idle`, `/odrive/clear_errors` | `std_srvs/Trigger` | disarm / clear errors |
| `/manipulator/cmd` | `std_msgs/Int8MultiArray` `[left, right]` | `transporter_joy` → `manipulator_controller` |
| `/manipulator/hw_cmd` | `std_msgs/Int8MultiArray` `[left, right]` | `manipulator_controller` → firmware |
| `/manipulator/hw_state` | `std_msgs/Int8MultiArray` `[left, right]` | firmware → `manipulator_controller` |

Manipulator values: `1` = up, `-1` = down, `0` = hold.

```
PS5 ─ joy_node ─/joy─ transporter_joy ─┬─/cmd_vel─ mobile_controller ─/wheels/cmd─ odrive_node ─USB─ 4× ODrive
                                       └─/manipulator/cmd─ manipulator_controller ─/manipulator/hw_cmd─ micro_ros_agent ─UART─ transport_mani
```

## 3. How to launch

| Command | Starts |
|---|---|
| `ros2 launch transporter_bringup mobile.launch.py` | Mobile base only: joy + mobile controller + ODrive |
| `ros2 launch transporter_bringup manipulator.launch.py` | Manipulator only: joy + manipulator controller + micro-ROS agent |
| `ros2 launch transporter_bringup manual.launch.py` | Both, driven by one controller |

Launch arguments:

| Argument | Default | Launch file |
|---|---|---|
| `mani_device` | `/dev/ttyTransporterLeftMani` | manipulator, manual |
| `mani_baudrate` | `115200` | manipulator, manual |
| `use_joy` | `true` | mobile, manipulator (set to `false` if `joy_node` is already running) |

Example: `ros2 launch transporter_bringup manual.launch.py mani_device:=/dev/ttyACM0`

Configuration files are in [src/transporter_bringup/config](src/transporter_bringup/config):

| File | Contents |
|---|---|
| `joy.yaml` | Button mapping and speeds (0.2 m/s, 0.1 rad/s) |
| `mobile.yaml` | Wheel geometry, plus the ODrive serials, signs, gear ratio and limits |
| `manipulator.yaml` | Command rate and timeout |

## 4. How to control (PS5)

**L1 is the deadman.** Nothing moves unless it is held.

| Input | Action |
|---|---|
| **L1** (hold) | Deadman: enables everything below |
| L1 + **D-pad ↑ / ↓** | Drive forward / backward (0.2 m/s) |
| L1 + **D-pad ← / →** | Turn left / right (0.1 rad/s) |
| L1 + **PS** | ODrive index search, then arm. **Required before driving.** |
| L1 + **△ Triangle** | Left manipulator **up** |
| L1 + **□ Square** | Left manipulator **down** |
| L1 + **○ Circle** | Right manipulator **up** |
| L1 + **✕ Cross** | Right manipulator **down** |
| Nothing pressed / L1 released | Stop, both manipulators **hold** |

### Start-up procedure (mobile)
1. Launch. Wait for `All ODrives connected`. The robot will **not** arm until all 4 are found.
2. Connect the controller and **release L1 once**. Control stays locked after every (re)connect until L1 is released.
3. Lift the wheels or clear the area, then press **L1 + PS**. Wait for `Index search done on all wheels` → `ARMED`.
4. Hold L1 and drive with the D-pad.

### Safety behaviour
| Event | Result |
|---|---|
| Not all 4 ODrives connected | Cannot index or arm |
| Index search not done or failed | Cannot arm. Drive commands are ignored with a warning |
| Any wheel drops out of closed loop | All wheels go idle. **Index search again** (L1 + PS) |
| ODrive USB lost or reconnected | All wheels go idle, reconnect, **index search again** |
| Controller lost (no `/joy` for 0.5 s) | Stop + hold. Release L1 after reconnect |
| `transporter_joy` / `mobile_controller` stops | Zero speed after 0.5 s |
| `odrive_node` dies | ODrive watchdog stops the motors (0.5 s) |
| Manipulator command stops | HOLD after 0.3 s (ROS) and 500 ms (firmware) |

> Button indices are for the ROS 2 `joy` package (SDL). Check them with `ros2 topic echo /joy`, and change them in `joy.yaml` if needed.

## 5. Manipulator firmware

| Command | PUMP_EN | SIDE_UP | SIDE_DOWN |
|---|---|---|---|
| Up | HIGH | HIGH | LOW |
| Down | HIGH | LOW | HIGH |
| Hold | LOW | LOW | LOW |

- The pump is on while any side is moving. UP and DOWN of a side are never HIGH at the same time.
- If no command is received for 500 ms, both sides go to HOLD.
- Pins are **placeholders** in `Core/Inc/config.h` (PC0, PC1, PC4, PA10, PB6). In CubeMX, give the real pins the user labels `PUMP_EN`, `LEFT_UP`, `LEFT_DOWN`, `RIGHT_UP` and `RIGHT_DOWN`. The generated defines then override the placeholders automatically.
